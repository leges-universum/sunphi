# SunPhi Wallet 0.1

A local, offline laboratory wallet for Windows, Linux and macOS using Node.js 24+.
No npm dependencies are needed to run the wallet. All interface text is English.

It creates an actual Ed25519 key pair, stores the private key in an encrypted file,
and signs sender reservations and recipient receipts. This is a software prototype
for the SunPhi protocol, not a released mainnet wallet, reserve wallet, or BTC/USDC wallet.
Laboratory tokens have no monetary value. There is no network balance or purchase service.

## Start on Windows

Open PowerShell in this repository:

```powershell
node --version
node wallet/cli.mjs help
node wallet/cli.mjs demo
```

The demo creates ephemeral keys in memory, exercises both signatures and a serial
lab arbiter, prints only the outcome, and makes no network requests or wallet files.
An accepted demo transfer does not prove agreement between independent nodes.

Create a private local directory outside the repository, then create two wallets:

```powershell
$walletDir = Join-Path $env:LOCALAPPDATA 'SunPhi-Lab'
New-Item -ItemType Directory -Force -Path $walletDir | Out-Null
node wallet/cli.mjs create --wallet "$walletDir\alice.sunphi-wallet.json"
node wallet/cli.mjs create --wallet "$walletDir\bob.sunphi-wallet.json"
```

Enter a different strong password for each wallet. Passwords are not echoed and
cannot be passed as command arguments, environment variables or redirected input.
The process ends after each command, so it does not retain an unlocked session.
If a file already exists it is preserved and the command fails.

## Backup, restore and password change

```powershell
node wallet/cli.mjs backup --wallet "$walletDir\alice.sunphi-wallet.json" --out "E:\alice-backup.sunphi-wallet.json"
node wallet/cli.mjs restore --wallet "E:\alice-backup.sunphi-wallet.json" --out "$walletDir\alice-restored.sunphi-wallet.json"
node wallet/cli.mjs rekey --wallet "$walletDir\alice.sunphi-wallet.json" --out "$walletDir\alice-new-password.sunphi-wallet.json"
```

Use your own existing backup directory in place of E:\. Backup and restore first
decrypt and validate the source, then save the encrypted file to a NEW destination.
Rekey creates a new encrypted file with the same address and a new password.
It does not erase or invalidate old backups, which still work with their old password.
No mnemonic phrase or password-reset service exists. A lost password or lost file
cannot be reconstructed from public fragments. Test restoration before relying on a backup.

## Sign a complete laboratory exchange

Read Bob's public address:

```powershell
node wallet/cli.mjs address --wallet "$walletDir\bob.sunphi-wallet.json"
```

Addresses begin with `sunphi_lab1_`. Never send another cryptocurrency to them.
The address command reads a public header; it does not authenticate the encrypted
payload without a password. Backup/restore and signing validate that the key matches.

Copy Alice's and Bob's addresses into these commands:

```powershell
node wallet/cli.mjs lab-state --to <ALICE_ADDRESS> --out "$walletDir\state.json"
node wallet/cli.mjs reserve --wallet "$walletDir\alice.sunphi-wallet.json" --state "$walletDir\state.json" --to <BOB_ADDRESS> --out "$walletDir\transfer.json"
node wallet/cli.mjs receive --wallet "$walletDir\bob.sunphi-wallet.json" --transfer "$walletDir\transfer.json" --out "$walletDir\receipt.json"
node wallet/cli.mjs verify --file "$walletDir\receipt.json"
```

Replace angle-bracket placeholders before running. Review the token ID, sender,
recipient and time limit; type SIGN to approve. The default reservation window
is five minutes. Each example transfers one whole laboratory token. Fractions,
multi-token selection and transaction fees are not implemented in this wallet.

`lab-state` creates an unaccepted fixture, never a real issued token. `reserve`
and `receive` save offline candidates. They do NOT reserve network funds, debit
a balance, establish freshness, or credit a spendable token. `verify` checks
signatures and bindings, not global acceptance or issuance. The lab arbiter in
`lab-ledger.mjs` demonstrates the missing acceptance boundary separately.

## Format and security boundaries

- Experimental domain: `sunphi-lab-v1`; deliberately separate from future mainnet.
- Ed25519 signatures through Node's native crypto implementation; SHA-256 hashes.
- Strict canonical JSON: sorted object keys, non-negative safe integer numbers,
  exact schemas, canonical Base64 and a 128 KiB file limit. Files generated by the
  CLI must not be edited/reformatted. Duplicate JSON keys are rejected at file import.
- The reservation binds token ID, previous main hash, ownership revision, unique
  transfer ID, both addresses, sending time and expiry.
- The receipt binds that exact signed reservation and recipient time. Reconstructing
  the main object never supplies either private key or finality.
- At rest: main object only. In transit: main object plus signed reservation; both
  hashes can be derived. Credit changes the owner, time, revision and ten-entry history.
- Cancelled transfer IDs stay in the lab arbiter's separate terminal-outcome register;
  trimming token history does not clear replay protection. The register is only in
  memory and must not be mistaken for a durable or distributed journal.
- AES-256-GCM encrypts the PKCS8 private key with authenticated header metadata.
  Scrypt uses N=131072, r=8, p=1, a random 32-byte salt; encryption uses a fresh
  12-byte IV and a 16-byte authentication tag. KDF cost is fixed, not supplied by a file.
- No plaintext key export command, telemetry, remote endpoint, website key entry,
  or cloud synchronization. Local keystore files are not business-platform database
  records and are never sent to Base44 or Supabase.
- Explicit byte buffers are cleared where possible; JavaScript strings and native
  KeyObjects cannot be guaranteed securely erased. Process exit is not a protection
  against malware, memory dumps or a compromised operating system.
- Files use exclusive creation and request mode0600. Windows ACL inheritance is
  not configured by this prototype: use a private Windows profile and protect
  backups. A password protects file contents, not a compromised unlocked machine.
- Public key/address metadata remains visible in the encrypted file. Package
  signatures and token histories are pseudonymous, not anonymous.

The algorithms and record suite are selected for this prototype only. Production
protocol acceptance, erasure coding, peer discovery, issuance admission, durable
reconciliation, GUI/installer, hardware signing and security audit remain separate work.
Do not use these laboratory keys for production assets.

## Verification

```powershell
node --test wallet/wallet.test.mjs
npm test
```

Tests cover encrypted restore, password changes, damaged data/header, malicious KDF
parameters, unauthorized signing, recipient/network/hash/time substitution, conflicting
reservations, replay, expiry/cancellation, ten-entry history and private input handling.
They establish tested local behavior, not the security of a future distributed network.

Crypto API reference: https://nodejs.org/docs/latest-v24.x/api/crypto.html
