SUNPHI WALLET PROCEDURE CONTRACT — 0.3.0
Implementation boundary, not an amendment to SPHI STD 001 1.1 RC2.

Client methods: connect(holder), query(holder), quote(holder, request),
execute(holder, exactSignedProposal, exactSignedHolderAuthority), recover(holder,id).
Only LaboratoryAdapter is implemented. Production cannot substitute an arbitrary
URL or trust bundle into this adapter. A qualified connector must separately bind
institution, environment, programme, route, law, authorities and finality sources.

Every signed evidence envelope contains keyId, signature and payload with domain,
kind, holder, transitionId, timestamp and body. Canonical JSON is signed with
Ed25519. Domain sunphi-procedure-lab-v1 cannot be used as a production domain.
Trust is pinned on explicit laboratory connection; it is not legal certification.

Proposal binds route ID/version, source and destination identities, exact decimal
quantities, terms, legal gates, fee/tax, expiry, reservation/escalation deadlines,
binding event, cancellation, valuation, remedy and authoritative legs. Consent
binds the digest of that entire proposal and cannot authorise a later version.
Institutional acceptance, reservation and execution decision bind the same digest.
Each final leg must identify its separate leg ID, authorised signer and quantity.
Completion requires both legs and one platform receipt for the exact proposal.
Partial outcome requires a recovery record and retains a claim against its owner.

Holder states: reviewed (memory only) -> SUBMITTING (encrypted before dispatch)
-> COMPLETED / RECOVERY_REQUIRED / UNKNOWN. A failed or absent reply never means
non-execution. UNKNOWN is resolved from a signed original-result snapshot. A
confirmed absent operation may be REJECTED only once the proposal has expired.
No automatic repeat, implicit inverse route or unilateral release is available.

Adapter idempotency: original transition ID + original proposal and authority
digests. Same ID with changed content is rejected. Identical replay returns the
original result. State is fsynced then atomically renamed before acknowledgement.
One application instance and one serial adapter instance own the local journal.
This file adapter is not a distributed consensus, HA or production custody store.

Snapshot binds holder, environment, standard version, monotonic sequence, as-of
time, expiry, positions, institutions, routes and signed transaction evidence.
Stale, foreign-holder, tampered or locally rolled-back records are rejected for
action. Saved stale records may be shown as history. UNKNOWN quantities are
labelled last confirmed, not currently spendable. Restore requires fresh query.

PRIMARY PRODUCTION GATES (not enabled by this preview)
1. Legal schedules: applicable country, classification, issue/distribute/accept
   authority, client eligibility, register/title, tax, redemption and insolvency.
2. Directional admission: both institutions and each service/product accept the
   same versioned route; conversion/novation/assignment legal effect is explicit.
3. Identity/mandate: verified holder and actor, current scope, limits, approvals,
   revocation and independent recovery; a key is not an identity or legal right.
4. Institution APIs: fresh signed source state, atomic reservations, original-ID
   query, qualified settlement/register evidence and participant-owned cases.
5. Partial completion: contractual survivor claims, case owner, deadlines and
   permitted remedies; test adapter completion is not a client production power.
6. Operations: audit, reconciliation, support, immutable checkpoints, paginated
   history, signed distribution, independent security and country qualification.

Product lifecycle coverage: legacy Pi demonstrates issuance/sale/redemption only
in its separate fictional ledger. New Vi/Pi/Go/Bl/Gr adapter demonstrates the six
listed transitions; Ma is informational. No claim of complete family coverage.
Common statuses do not harmonise national law or create enforceable finality.
